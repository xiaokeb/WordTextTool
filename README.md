# Word 文本处理工具

一个面向 Windows 的文档批量处理工具，提供 Word 文本替换、Excel/WPS 编号与 PDF 导出、文件名后缀管理。使用 Python、PyQt6 和本地办公软件自动化，保护源文档与已有输出。

## 当前状态

[V2.0 已于 2026-10-12 正式发布](https://github.com/xiaokeb/WordTextTool/releases/tag/V2.0)，发布代码为 `eda73a6`。最终 EXE 通过 Windows 11/WPS 自动与固定模式三表编号、PDF、源文件保护和正常启闭验证，185 项自动化测试通过，代码与标签已普通推送，6 个 Release 附件的远端 SHA256 与本地一致。具体回执见 `docs/开发全流程.md` 第 19 章。Microsoft Excel 的身份识别及兼容调用通过接口契约测试，本机没有真实 Excel，未做真机验收。按用户最新要求，以 Windows 11/WPS 为本次真实验收范围；Windows 10 和无 Python 干净机器未验证。

- 三个功能页的参数独立，同一时刻全程序只运行一个批次；
- Word 与重命名无需安装办公软件；编号和 PDF 需要本地可自动化的 WPS 表格或 Microsoft Excel；
- 源 Word/Excel 不覆盖；文件名后缀管理会直接重命名所选文件，执行前显示完整预览；
- V1.0 历史发布状态与标签保持独立，不能将 V2.0 EXE 当作 V1.0 附件。

## V2.0 编号与 PDF

1. 在“记录编号”页添加 `.xlsx`，可扫描文件夹当前层，使用“上移/下移”调整文件顺序；全部工作表必须可见、有效且未保护。
2. 模板包含一个 `yy`，例如 `项目-yy`；起始序号默认 1，结果为 `项目-01`，99 之后为 100。同一工作簿的所有工作表使用同一编号，文件失败不重新分配后续编号。
3. 自动模式将生成编号写入 E1:F1。固定模式先在每张工作表最上方插入一行，再将固定编号写入新 E1:F1、生成编号写入 E2:F2。目标区域均合并、水平/垂直居中、加粗，字体 Times New Roman；编号按文字保存。
4. 点击“预览编号”，双击行查看完整工作表、输出路径和将被替换的目标内容。目标公式、冲突合并或 F1 已有内容会阻止该文件处理；覆盖已有普通文字需要确认。
5. “写入编号”仅保存编号副本；“导出 PDF”仅导出选中的工作簿；“一键转换”将本次编号副本导出为 PDF。PDF 按工作表顺序合并，所有列一页宽、高度不限，上下边距 1.3 cm、左右 0.9 cm。
6. 默认在源文件同级“修改版”目录保存 `原名 - 编号版.xlsx` 和相应 PDF，可选择自定义目录；同名自动编号避让。PDF 失败时保留已完成的编号副本，结果显示两个步骤的状态。

插行后原表头和公式随内容移动；原打印区域从第一行开始时会扩展，确保新增固定编号进入 PDF。未涵盖编号列的自定义打印区域继续保留，请按模板的实际打印范围检查输出。

## V2.0 后缀管理

在“后缀管理”页选择文件，输入要删除的内容，默认是带前置空格的 ` - 修改版`。默认仅删除主文件名末尾一次；勾选“全部匹配”可删除中间及末尾所有匹配串。扩展名保持不变，空格和大小写精确匹配。

先点击“预览名称”，再点击“执行重命名”并确认清单。目标冲突自动预留编号名；若执行时目标被其他程序抢占或源文件发生变化，则拒绝该项并要求重新预览。取消保留已完成结果，不执行整个批次回滚。

## V2.0 安全与兼容边界

- Excel/PDF 仅支持普通 `.xlsx`，拒绝宏、外部数据连接、危险公式和嵌入活动对象；不支持 `.xls/.xlsm/.xlsb`、加密或受保护工作簿。
- 办公软件在独立后台实例中操作临时副本；禁用宏、事件和外链更新，不能安全隔离时拒绝运行。单次办公操作超时上限 120 秒。
- 不接管或关闭用户已有工作簿；开始处理后冻结参数，取消与关闭等待安全边界。
- 安装依赖不等于已验证引擎。程序会检查真实进程身份，WPS 注册的 Excel 兼容接口不会被冒充为 Microsoft Excel。
- 候选包和人工验收说明见 `docs/V2.0发布说明.md`。正式标签、推送和 Release 仅在实际完成后记录。

## 首版范围

- 使用 PyQt6 构建可缩放的单页桌面界面；
- 批量选择或从单层文件夹扫描 `.docx` 文档；
- 通过只读两列表格展示用户动态添加的替换规则；
- 处理正文、普通及嵌套表格、页眉、页脚和超链接显示文字；
- 支持同一段落内跨 Run 和软换行的文本匹配；
- 使用非级联、从左到右、同位置最长优先的替换算法；
- 新文本继承匹配首字符的格式，未匹配内容保持原格式；
- 后台顺序处理文件，支持进度显示和安全取消；
- 永不覆盖源文件或已有输出文件。

旧版 `.doc` 文件在首版中会被识别并提示，但不会加入处理队列。

## 使用方法

V2.0 开发构建位于 `dist/V2.0-candidate/Word 文本处理工具.exe`，正式附件按版本保存于 `dist/V2.0/`；根目录 dist 的旧 V1.0 EXE 独立保留。最终 Release 的 EXE 自带运行依赖，无需另行安装 Python 或 Microsoft Word；Excel 编号和 PDF 需要 WPS 表格或 Microsoft Excel。

1. 点击“浏览文件”/“添加文件”多选文档，或“浏览文件夹”扫描当前层。只接受不超过 50 MiB 的 `.docx`；`.doc`、重复、超大或不可读文件会提示跳过。
2. 在“替换前：”“替换后：”输入文本，点击“添加规则”。规则在只读表格中依次展示；选中整行后点击“删除规则”才会删除。
3. 长规则支持滚动与双击只读详情。两侧各最多 10,000 字符；替换前不能是纯空白。替换后留空表示删除，添加前需要确认。
4. 可选择自定义保存目录；不选择时，保存到每个源文件同级的“修改版”文件夹。
5. 点击“开始处理”。处理期间文件、规则与保存设置锁定；点击“取消处理”会等当前文件安全完成后停止。处理中关闭窗口也须确认并等待当前文件完成。
6. 完成后查看“处理成功、未匹配、已跳过、处理失败”四类详情，可复制文字。关闭程序后规则清空，不自动保存或导出。

## 替换与保存说明

- 使用精确匹配；英文字符区分大小写，空格、标点和软换行必须与原文一致，没有正则/模糊匹配开关。
- 同一位置以较长规则优先；新生成文字不会参与本轮后续替换。例如同时设置 `xxx公司 → yyy公司`、`yyy公司 → zzz公司`，原文 `xxx公司` 只变为 `yyy公司`。
- 请准确录入完整查找内容：若原文为 `xxx公司`，只查找 `xxx` 并替换成 `yyy公司`，精确替换会保留原有“公司”后缀。程序不猜测或自动删除规则之外的文字。
- 新文字继承匹配首字符的 Run 格式；跨独立段落不匹配。自动域、文本框、艺术字、批注、脚注、尾注和修订/内容控件文字不处理；带图片等复杂内容的 Run 为保守保护边界。
- 输出为 `原名 - 修改版.docx`，已有同名时追加 ` (1)`、` (2)`；源文件和已有输出均不覆盖。没有命中不产生副本。
- 输出先写入目标目录临时文件，重开验证成功后再发布最终文件。异常会给出中文原因；极端权限问题可能导致隐藏临时文件无法清理。

## 开发、测试和打包

目标为 Windows 10/11 x64；项目统一使用 Conda **WordMod** 环境、Python **3.13.15**。命令均在项目根目录执行，整个项目不使用 worktrees。

```powershell
conda activate WordMod
python -m pip install -r requirements-lock.txt
python -m pip check
python src\main.py
python -m pytest -v
.\build.bat
```

首次创建环境可执行 `conda env create -f environment.yml`。已有 `WordMod` 时使用上述安装命令，不另建 `.venv`。`requirements.txt` 固定项目直接依赖，`requirements-lock.txt` 固定完整安装版本；更新依赖时应同时更新两个文件并重新测试。

开发流程：Superpowers 仅用于规划和边界规定，确认后直接在本目录实现；全部功能完成后集中联调、安全检查和最终审查，再提交发布。不编辑 `.superpowers/`，节点与版本记录统一在 `docs/开发全流程.md`、`docs/实施计划.md`，大版本单独编写发布说明。

PyCharm 已配置的解释器为 `E:\Backend_Env\Python\miniconda3\envs\WordMod\python.exe`，运行入口为 `src/main.py`，使用模块 SDK 即可；工作目录可为项目根目录或 `src`。无需修改已有 PyCharm 配置。

未激活环境时可执行 `conda run --no-capture-output -n WordMod python src/main.py` 或 `conda run --no-capture-output -n WordMod python -m pytest -v`。`build.bat` 始终调用 `WordMod` 并在 `dist/V2.0-candidate/` 构建和整理附件，不覆盖旧 V1.0。构建回执、依赖锁和来源/附件校验分别记录于 build 和候选 manifest，正式成品验证后才准备发布附件；不分发 `.py` 源文件。

本工具采用 PyQt6；对外分发应遵守其 GPL 或商业许可及其他依赖的许可要求。
