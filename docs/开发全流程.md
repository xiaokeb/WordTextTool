## 1. 文档状态

## 2. 产品目标

首版交付一个无需安装 Python 即可运行的 Windows 桌面程序。用户可以批量选择 `.docx` 文档、录入多条文本替换规则，在不覆盖源文件的前提下生成修改版文档。

首版优先保证：

1. PyQt6 界面清晰、响应迅速且可缩放；
2. 替换结果不会重复拼接或发生链式替换；
3. 新文本继承匹配首字符的格式，其他内容不被误改；
4. 单个文件失败不影响整个批次；
5. 输出过程安全，不留下最终命名的残缺文件。

## 3. 首版范围

### 3.1 包含的能力

- PyQt6 单页桌面界面；
- 多选 `.docx` 文件；
- 扫描所选文件夹的当前层级；
- 文件大小、存在性、可读性和重复性检查；
- 用户动态添加与删除替换规则；
- 正文、普通表格、嵌套表格、页眉、页脚的文本替换；
- 超链接显示文字替换，同时保留链接地址和样式；
- 同一段落内跨 Run 和软换行的文本替换；
- 后台顺序批处理、实时进度与安全取消；
- 默认输出目录和自定义输出目录；
- 成功、未匹配、已跳过、失败四类结果统计；
- PyInstaller 单 EXE 打包。

### 3.2 明确不包含的能力

以下项目标记为“首版不实现”，不得进入首版代码和首版验收：

- Excel 编号写入；

- 规则持久化、自动保存、导入或导出；
- 子文件夹递归扫描；
- 正则表达式、通配符和模糊匹配；
- 自动生成日志文件或日志导出。

## 4. 技术方案

### 4.1 技术栈

- Python 3.x；
- PyQt6；
- `python-docx`；
- 对超链接、软换行和跨 Run 映射使用受控的 OOXML 遍历；
- `pytest` 与 `pytest-qt`；
- PyInstaller。

首版不使用 Microsoft Word COM、LibreOffice 或其他外部办公软件作为运行依赖。

### 4.2 架构原则

- 界面只负责展示、输入和发出操作请求；
- 文档处理逻辑不依赖窗口控件；
- 文件校验、替换匹配、DOCX 遍历和批处理分别保持清晰边界；
- 核心算法可在不启动 GUI 的情况下完成单元测试；
- 后台工作线程通过 PyQt6 信号传递进度和结果，不直接操作界面控件；
- 源文件只读，所有输出均写入独立目标文件。

## 6. 界面设计

### 6.1 总体布局

主窗口为单页结构，不使用选项卡。初始大小为 `1000×900`，允许用户缩放，并设置保证核心内容可访问的最小尺寸。界面使用布局管理器、伸缩因子和最小尺寸约束，不使用绝对坐标。

按钮保持固定高度和合理最小宽度；文件列表、规则表格和输入区域承担主要伸缩。窗口变化时，部分控件按比例拉伸，但不得遮挡标签、按钮或输入内容。长路径和长规则通过内部滚动、换行、悬浮提示或只读详情窗口完整访问。

默认字体使用 Microsoft YaHei UI。主标题为“Word 文本处理工具”，16pt、粗体。

### 6.2 文件选择区域

- 只读路径框；
- “浏览文件”和“浏览文件夹”按钮；
- 文件数量状态及路径详情；
- 单列只读文件表格，只显示文件名；
- “添加文件”和“删除文件”按钮；
- 表格采用单行选择；
- 删除必须先选择一行并点击按钮；
- 不支持双击删除。

### 6.3 替换规则区域

- 两列只读表格，表头固定为“替换前”和“替换后”；
- 两列按 `1:1` 比例伸缩；
- 不设置固定类别、默认规则或类别列；
- 不允许直接编辑表格单元格；
- 长内容自动换行，表格行设置最大显示高度；
- 超出可见范围时显示省略提示，但内部规则模型保存完整内容；
- 双击规则行打开只读详情窗口，完整展示两侧文本；
- 表格下方并列放置“替换前：”和“替换后：”多行输入区；
- 输入区支持滚动和同一段落内的软换行内容；
- 输入区下方居中并列放置“添加规则”和“删除规则”按钮；
- 添加成功后清空两侧输入，并把焦点返回“替换前”输入区；
- 删除规则必须先选中一行，未选中时不执行并给出提示。

表格中的限高预览不得作为替换输入。替换引擎必须始终读取规则模型中的完整字符串。

### 6.4 保存、进度与操作区域

- 只读保存路径框和“浏览”按钮；
- 未选择自定义路径时显示默认保存规则；
- 长路径可滚动、复制，并通过悬浮提示查看完整值；
- 进度条显示 0–100%；
- 状态文本显示当前文件和进度；
- 操作按钮为“开始处理”“取消处理”“清空所有”；
- “取消处理”默认禁用，仅在处理期间启用；
- 处理期间锁定文件、规则和保存路径控件；
- 存在文件或规则时，“清空所有”需要二次确认；空状态下直接重置。

### 6.5 结果详情

结果窗口展示成功、未匹配、已跳过和失败四类。每项包含文件名和可用原因，内容允许选择和复制。首版不自动写出日志文件。

## 7. 文件选择与输出规则

### 7.1 文件选择

- 文件对话框允许选择 `.docx` 和 `.doc`；
- `.doc` 在添加阶段立即提示首版不支持，并排除出处理列表；
- 选择文件夹时只扫描当前层级；
- 文件最大允许大小为 `50 × 1024 × 1024` 字节；
- 校验文件存在、为普通文件且可读取；
- 使用规范化绝对路径去重；
- 重复文件不再次加入，并提示跳过数量。

### 7.2 输出规则

- 未指定路径时，在每个源文件所在目录创建“修改版”子文件夹；
- 指定自定义路径时，所有输出直接保存到该目录；
- 基础文件名为 `原文件名 - 修改版.docx`；
- 已存在同名文件时永不覆盖，依次追加 ` (1)`、` (2)`；
- 不修改源文件；
- 文档没有任何规则命中时不生成副本，并计入“未匹配”。

## 8. 规则定义与校验

- 规则由用户逐条输入，关闭程序后清空；
- 首版不提供导入、导出或自动保存；
- “替换前”不能为空，也不能只包含空格、制表符或换行；
- 有效“替换前”的首尾空格和换行必须原样保留；
- 相同“替换前”内容不能重复添加；
- “替换前”和“替换后”各自最多 10,000 个字符；
- “替换后”为空表示删除匹配内容，添加规则前必须确认；
- “替换后”只包含空白时是有效规则，不视为删除；
- 空格、换行和标点必须精确匹配；
- 内容可能含英文编号，用户负责准确录入；界面不提供大小写或全角/半角选项；
- 不支持正则、通配符或模糊匹配。

## 9. 替换算法

### 9.1 匹配边界

首版处理正文、普通及嵌套表格、页眉、页脚。普通文本与超链接分别作为独立匹配区域，规则不得跨越普通文本和超链接边界。超链接只修改显示文字，链接地址和样式保持不变。

支持同一段落内跨 Run 和软换行匹配，不支持跨两个独立段落匹配。文本框、艺术字、批注、脚注、尾注、自动域和域代码均不参与替换。

### 9.2 非级联匹配

每个待处理文本区域先构建不可变的原文快照以及字符到 Run 的映射，然后执行：

1. 从左到右扫描原文；
2. 同一位置存在多条规则时，选择“替换前”更长的规则；
3. 命中后跳过完整匹配范围，禁止产生重叠区间；
4. 替换结果写入输出缓冲区；
5. 新生成的文本不再参与任何规则匹配；
6. 完成整段扫描后一次性写回对应 Run。

该策略禁止边替换边搜索，从机制上防止重复后缀、重复插入和规则链式触发。

### 9.3 格式保持

- 新文本统一继承匹配首字符所在 Run 的格式；
- 匹配范围外的文本继续保留在原 Run 中；
- 不得无条件把整段文本重建到单一 Run；
- 替换内容中的换行写为同一段落内的软换行；
- 未匹配 Run、段落属性、表格结构、页眉页脚结构和超链接关系不应被改动。

## 10. 批处理与取消

- 使用单个后台工作线程按文件顺序处理；
- 工作线程通过 PyQt6 信号报告当前文件、数量、百分比和最终结果；
- 工作线程不得直接修改界面控件；
- 开始处理时冻结文件列表和规则快照；
- 处理期间禁止修改文件、规则和保存路径；
- 取消请求在当前文件安全完成后停止后续文件；
- 已经成功生成的输出予以保留；
- 处理过程中关闭窗口时弹出确认框；确认后执行安全取消并等待线程结束，再退出程序。

## 11. 安全保存

每个有命中的文件执行以下保存流程：

1. 计算不会覆盖已有文件的最终路径；
2. 在目标目录生成唯一临时 DOCX；
3. 保存处理结果到临时文件；
4. 重新打开临时 DOCX，验证文件结构可读取；
5. 验证成功后将其原子移动为最终文件名；
6. 任一步骤失败时清理临时文件并记录失败原因。

自定义输出目录必须存在且可写。默认输出目录按需创建。写权限通过创建并清理临时测试文件验证。

## 12. 状态分类与异常处理

- **处理成功**：至少命中一次、成功保存且重新打开验证通过；
- **未匹配**：没有任何规则命中，不生成副本；
- **已跳过**：添加阶段过滤的 `.doc`、超大、重复或其他不符合条件的文件；
- **处理失败**：损坏、加密、被占用、读取失败、替换失败或保存失败。

单个文件失败后继续处理其他文件。用户界面显示清晰中文原因，不暴露内部堆栈信息。处理完成或取消后恢复控件状态。

## 13. 测试与验收

- 空替换删除内容；
- 纯空白查找被拒绝；
- 匹配首字符格式继承；
- 匹配范围外格式保持。

### 13.2 DOCX 范围测试

- 正文；
- 普通和嵌套表格；
- 页眉及其表格；
- 页脚及其表格；
- 超链接显示文字和链接关系；
- 自动域保持不变；
- 不跨段落或普通文本与超链接边界。

### 13.3 文件与批处理测试

- 同名输出自动编号；

### 13.4 界面与发布验收

- 窗口缩放后按钮、表格、输入区和文字仍可访问；

格式验收需要检查生成 DOCX 的 Run 属性、段落属性、超链接关系和未修改 XML，不得只比较界面文本。
